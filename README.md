# شجره‌نامه خاندان الله‌رضایی

یک اپ تک‌فایلی (`index.html`) فارسی و راست‌به‌چپ برای ثبت شجره‌نامه، خاطره‌ها، دفتر رشد کودکان، موزهٔ خانوادگی و کتابچهٔ «ریشه‌ها». فرانت‌اند روی هر هاست استاتیک اجرا می‌شود و داده‌ها در **Supabase** نگهداری می‌شوند.

## ساختار ریپو

| مسیر | توضیح |
|---|---|
| `index.html` | کل اپ (HTML، CSS و جاوااسکریپت) |
| `manifest.json`، `sw.js`، `icons/` | نصب‌پذیری (PWA) و باز شدن آفلاین پوستهٔ اپ |
| `supabase/` | مستندات و اسکریپت‌های سمت سرور (جدول‌ها، سیاست‌های دسترسی، bucketها) |
| `README.md` | همین فایل |

## راه‌اندازی

1. یک پروژهٔ Supabase بسازید و جدول‌ها، توابع و bucketهای فهرست‌شده در `supabase/README.md` را بسازید.
2. اسکریپت `supabase/001_museum_security.sql` را (بعد از خواندن توضیحات بالای آن) اجرا کنید.
3. در بالای `index.html` مقدار `window.SHJ_CONFIG` را تنظیم کنید: `url`، `key` (کلید publishable)، `familyEmail` و `adminEmail`.
4. در Supabase Auth دو کاربر بسازید: حساب مشترک خانواده (`familyEmail`، رمز آن همان «رمز خانواده» است) و حساب مدیر (`adminEmail`).
5. `index.html` را روی هاست استاتیک قرار دهید.

## نصب روی گوشی (PWA)

- فایل‌های `manifest.json`، `sw.js` و پوشهٔ `icons/` باید **کنار `index.html` و در همان مسیر** منتشر شوند. همهٔ آدرس‌ها نسبی‌اند، پس زیرمسیر (مثلاً `/shajare/`) هم مشکلی ندارد.
- نصب فقط روی **HTTPS** (یا localhost) کار می‌کند.
- service worker فقط پوستهٔ اپ را کش می‌کند؛ درخواست‌های Supabase (داده، عکس، ورود) هرگز کش نمی‌شوند.
- بعد از هر تغییر مهم در `sw.js` عدد `VERSION` را بالا ببرید (`shj-v2` ...). صفحهٔ اصلی همیشه اول از شبکه گرفته می‌شود، پس به‌روزرسانی `index.html` نیازی به این کار ندارد.

## نکات امنیتی (مهم)

- سورس عمومی است؛ کلید publishable و ایمیل مدیر در آن دیده می‌شود. **تنها دیوار واقعی، RLS در Supabase است.** همهٔ جدول‌ها و bucketها (از جمله `shj-life-media` که عکس‌های دفتر رشد کودکان را نگه می‌دارد) باید سیاست مشخص داشته باشند.
- رمز مدیر قوی باشد و 2FA فعال شود. در تنظیمات Auth محدودیت تعداد تلاش (rate limit) را بررسی کنید.
- رمز خانواده یک راز مشترک است؛ اگر لو رفت آن را در Supabase Auth عوض کنید و به اعضا اطلاع بدهید.
- توابع `shj_verify_parent_pin` و `shj_change_password` باید تعداد تلاش ناموفق را محدود کنند.
- فایل‌های آپلودی فقط JPG، PNG، WebP، GIF و PDF هستند و محدودیت نوع و حجم باید روی خود bucket هم اعمال شود (در فایل SQL آمده).

## پشتیبان‌گیری

سه لایه لازم است:

1. **از داخل اپ (مدیر):** تب مدیریت ← «پشتیبان و خروجی» ← «دانلود پشتیبان JSON». شامل افراد، خاطره‌ها و یادگارهای موزه (متن و لینک فایل‌ها) است. هر ماه یک بار.
2. **دیتابیس:** `supabase db dump -f supabase/schema.sql` برای ساختار و `supabase db dump --data-only -f backup-data.sql` برای داده‌ها. فایل داده را در ریپو **نگذارید** (اطلاعات خانوادگی است).
3. **فایل‌های عکس (Storage):** بک‌آپ دیتابیس فایل‌ها را شامل نمی‌شود. از پنل Supabase یا S3-compatible endpoint (مثلاً با `rclone`) bucketهای `shj-family-public`، `shj-family-pending` و `shj-life-media` را جدا کپی کنید.

## نگهداری

- هر تغییر در ساختار دیتابیس را به‌صورت یک فایل شماره‌دار در `supabase/` ثبت کنید (`002_...sql`).
- بعد از تغییر `index.html`، یک بار ثبت یادگار، تأیید مدیر و لغو انتشار را دستی امتحان کنید.
